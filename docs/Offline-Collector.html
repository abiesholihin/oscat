Offline collector

Some hosts cannot be reached from the jumphost: a separate network, a client's site, no inbound SSH or WinRM. For those, OSCAT issues a collector: a script someone runs on the host, which writes one results file. OSCAT evaluates that file exactly like a network scan, with the same views and reports.

The script installs nothing and changes nothing on the host.

One collector per OS and benchmark

A collector is made from one profile, so it is named after the OS release and benchmark version it covers:

  • oscat-collect-ubuntu-22.04-cis-3.0.0.sh (POSIX sh, for Linux and Unix profiles)
  • oscat-collect-windows-server-2022-cis-3.0.0.ps1 (PowerShell, for Windows profiles)

A database benchmark's collector runs on the database server, Linux or Windows, and runs its queries with the database's own client; see Databases. Network devices cannot run a collector; see Network devices for auditing them from a saved terminal session.

The script checks the host's OS first (/etc/os-release, or the Windows edition) and refuses any other system, so a SUSE 15 host cannot be audited against the Ubuntu 22.04 benchmark by mistake. --force (-Force on Windows) overrides that. The results file records the host's OS, and OSCAT refuses a file collected on a different OS unless you accept it explicitly.

A profile names its OS as os: {id: ubuntu, version: "22.04"} (the os-release ID and a VERSION_ID prefix, or windows-server / windows and the release). Without it, OSCAT works it out from the benchmark title.

Issue a collector (web app)

  1. Open the profile on the Profiles page and click Offline collector.
  2. Say who it is for (for example ACME 2026 audit) and for how many days the script is valid (90 by default; 0 means no limit).
  3. Under Controls, keep the whole profile, pick a saved control set, or click Choose controls (the same picker as a new scan). The checks of left-out controls are not in the script at all, and those controls show as Excluded in the results.
  4. Download the script and hand it over.

The same page lists the profile's collectors with their controls and uploads. From there you can download one again, extend its validity (for a rescan after remediation) or revoke it. After extending, download the script again: copies already handed out keep their old end date.

Run it on the host

As root on Linux or Unix:

sh oscat-collect-ubuntu-22.04-cis-3.0.0.sh
# writes oscat-<host>-<os>-<time>.oscat in the current folder

In an elevated PowerShell on Windows:

powershell -ExecutionPolicy Bypass -File oscat-collect-windows-server-2022-cis-3.0.0.ps1

Checks that need root are recorded as errors if it runs as an ordinary user. The script can be run on any number of hosts, and again after remediation.

The script runs only until its end date (shown at the top of the script). After that it stops with "This collector stopped working on …" and exit code 5, even with --force; ask for the collector to be extended and download it again.

Bring the results back

Scans → Upload collected results, and select the .oscat files (one per host) from one collector. Each file names its collector, which names the profile, so OSCAT knows how to judge it. The upload becomes a finished scan. A host named like an existing target is linked to that target and takes its groups.

Handing a collector to a client

The collector is designed to be given to someone outside your team:

  • Readable, but nothing to judge with. The client's security team can read every command, but the commands are numbered, in random order, and carry no CIS control numbers or titles. What the output should be, and how checks combine into a pass or fail, never leaves OSCAT. The raw output on its own is not an audit report.
  • Signed results. Every results file is signed with the collector's own key, and OSCAT rejects a file that was edited after collection or written by another collector. The key is inside the script, so this stops accidental and casual edits, not a determined administrator; the point above is the real protection.
  • A validity window. The script runs only for the chosen number of days; after that it stops with a message saying so (it checks the host's clock). Results collected while it was valid can be uploaded to OSCAT any time, as many times as needed, for example to rebuild a report. OSCAT refuses a file collected after the end date (the collection time is signed into the file), and every file of a revoked collector.

OSCAT keeps a record of each collector: its ID, the key (encrypted like credentials), the validity, and which control each numbered command belongs to.

From the command line

oscat collector -p profiles/cis-ubuntu-22.04/profile.yaml --label "ACME 2026" --days 90
# writes the script and oscat-collect-ubuntu-22.04-cis-3.0.0.collector.json

oscat import-collected oscat-web1-*.oscat oscat-db1-*.oscat \
    -p profiles/cis-ubuntu-22.04/profile.yaml \
    -k oscat-collect-ubuntu-22.04-cis-3.0.0.collector.json -o results.json
oscat report results.json --xlsx report.xlsx -p profiles/cis-ubuntu-22.04/profile.yaml

The .collector.json file is the collector's record. Keep it, and never give it to the client: it maps the numbered commands back to controls.

Limits

  • API checks (such as Cisco APIC) need the network and are reported as errors.
  • If the profile changes after collection, checks whose command changed are reported as errors (collect again), while checks whose assertion alone changed are judged again.
