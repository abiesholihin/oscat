Databases

CIS database benchmarks mix two kinds of controls: settings you read with a query in the database (SHOW ssl, a SELECT on a system view), and checks on the server the database runs on (file permissions on the data folder, the service account, log settings in a config file). OSCAT audits both in one scan: it logs in to the database to run the queries, and to the server's OS to run the rest.

Supported engines: PostgreSQL, MySQL, MariaDB, Microsoft SQL Server, Oracle Database and MongoDB. The drivers for all of them come with OSCAT.

Import the benchmark

Import the engine's CIS PDF on the Benchmarks page like any other (see Importing a CIS PDF). OSCAT recognises a database benchmark from its title, drafts each audit query as a SQL check, and drafts the pass rule where the benchmark states the expected value. Review the drafts as usual: a query whose expected result the PDF only describes in words needs its rule written by hand.

A database benchmark imported with an older OSCAT shows as a Linux benchmark; import its PDF again so it is recognised as a database benchmark.

Site values

Some checks need a name only your site knows, such as your DBA role, an audit file path or a list of approved users. The importer writes these as {{name}} in the check, and the benchmark page lists them under Site values. Fill them in once; every scan and offline collector of that benchmark uses them. A check whose site value is empty reports an error that names the value, so nothing is judged on a guess.

Scan a database

Pick the database benchmark on New scan. The hosts are the database servers. The Login card then asks for two logins.

Database

Field What to enter
Engine set by the benchmark
Port the engine's default (5432, 3306, 1433, 1521, 27017), or your own
Log in to the database with A database user and password (the default), or The server's OS login
Database the database to connect to; for Oracle, the service name
Database credential a password credential for a read-only database user (see below)
Authentication (SQL Server only) SQL authentication, or Windows authentication with the jumphost's Kerberos identity

The server's OS login suits sites that give auditors no database account: OSCAT logs in to the server over SSH or WinRM and runs the queries with the database's own client (psql, mysql, sqlplus, sqlcmd, mongosh), the way a DBA would at the console. On Linux it runs the client as the account the database already trusts without a password: postgres for PostgreSQL, oracle for Oracle (/ as sysdba), otherwise root. Set Run the database client as to use another account.

Server the database runs on

Choose Linux (SSH) or Windows (WinRM) and fill in that login as for any scan, with privilege escalation on Linux. These are the controls that check the server's files, services and accounts.

Choose No OS login when you only have database access. The server-side controls are then reported as Manual with the Observation "not assessed: …" and the reason, so the report shows exactly what was left out.

Clusters

For a cluster (SQL Server Always On, Oracle RAC, a MySQL or PostgreSQL replica set), list the nodes as the scan's hosts and open Cluster. In Reach the database at, enter the listener, Oracle SCAN name or virtual IP. Each node's OS is audited over its own login, and the database settings are read through the shared address.

Controls checked in every database

Some controls apply to each database on the server, or each pluggable database (PDB) in an Oracle container database. The importer marks the ones the benchmark says to run in each database; OSCAT then runs them in every database it can open, and each row of the result starts with the database's name, so the Observation shows which database failed.

A read-only database account

OSCAT only runs the queries in the benchmark. Give it an account that can read the server's settings and system views, and nothing more. Replace the password with your own.

PostgreSQL

CREATE ROLE oscat_audit LOGIN PASSWORD 'change-me';
GRANT pg_monitor TO oscat_audit;

pg_monitor reads every setting and statistics view. A few CIS checks read password hashes from pg_authid, which only a superuser can read; without one they report an error that says so.

MySQL and MariaDB

CREATE USER 'oscat_audit'@'JUMPHOST_ADDRESS' IDENTIFIED BY 'change-me';
GRANT SELECT ON mysql.* TO 'oscat_audit'@'JUMPHOST_ADDRESS';
GRANT SELECT ON performance_schema.* TO 'oscat_audit'@'JUMPHOST_ADDRESS';
GRANT PROCESS, SHOW DATABASES ON *.* TO 'oscat_audit'@'JUMPHOST_ADDRESS';

Microsoft SQL Server

CREATE LOGIN oscat_audit WITH PASSWORD = 'change-me', CHECK_POLICY = ON;
GRANT VIEW SERVER STATE, VIEW ANY DEFINITION, CONNECT ANY DATABASE TO oscat_audit;

CONNECT ANY DATABASE lets the checks that run in every database open each one. With Windows authentication, grant the same to the jumphost's AD account instead.

Oracle Database

For a container database (12c and later), create a common user that can read every PDB:

CREATE USER c##oscat_audit IDENTIFIED BY "change-me" CONTAINER = ALL;
GRANT CREATE SESSION, SET CONTAINER, SELECT_CATALOG_ROLE TO c##oscat_audit CONTAINER = ALL;
GRANT AUDIT_VIEWER TO c##oscat_audit CONTAINER = ALL;
ALTER USER c##oscat_audit SET CONTAINER_DATA = ALL CONTAINER = CURRENT;

For a non-container database, create oscat_audit and grant CREATE SESSION, SELECT_CATALOG_ROLE and AUDIT_VIEWER.

MongoDB

use admin
db.createRole({ role: "oscatAudit", roles: [],
  privileges: [{ resource: { db: "", collection: "" }, actions: ["viewUser", "viewRole"] }] })
db.createUser({ user: "oscat_audit", pwd: passwordPrompt(),
  roles: ["clusterMonitor", "oscatAudit"] })

Offline collector

A database benchmark's offline collector runs on the database server. When you issue it, choose Server the database runs on: Linux gives a shell script, Windows a PowerShell script. Run it as root or an administrator, as for any collector (see Offline collector).

It runs the queries with the database's own client on that server:

  1. It first logs in through the server's OS login: postgres or oracle local login on Linux, Windows authentication for SQL Server.
  2. If that fails, it asks once for a database user and password. The password is not shown as you type, never written to the results file, and gone when the script ends.
  3. If the client is not installed, those checks are reported as errors that say so.

Options for a database other than the local default:

sh oscat-collect-pgsite.sh --db-host 127.0.0.1 --db-port 5433

powershell -ExecutionPolicy Bypass -File oscat-collect-mssql.ps1 -DbHost 'localhost\SALES'

For a SQL Server named instance give the instance in --db-host/-DbHost and leave the port out.

Command line

hosts:
  pg1:
    address: 10.0.0.20
    connection: database
    db_engine: postgresql        # postgresql | mysql | mariadb | mssql | oracle | mongodb
    db_name: appdb               # database, or Oracle service name
    username: auditor
    password: {env: OSCAT_DB_PASSWORD}
  sql1:
    address: 10.0.0.21
    connection: database
    db_engine: mssql
    db_auth: windows             # SQL login by default; windows = integrated auth
