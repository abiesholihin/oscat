Installation

OSCAT is agentless: it runs on one machine (the jumphost) and logs in to the hosts it audits. Nothing is installed on those hosts.

Choose an installer

Every release on the Releases page (tags look like v0.1.0-85) has these files and a SHA256SUMS file to check them with:

File For Needs on the jumphost
oscat-<version>.x86_64.rpm RHEL, Rocky, Alma 8+, SUSE (SLES 15 SP3+) systemd, glibc 2.28+
oscat_<version>_amd64.deb Ubuntu 20.04+, Debian 10+ systemd, glibc 2.28+
oscat-<version>-docker.run any Linux with Docker and Compose v2 Docker
oscat-<version>-setup.exe Windows Server 2016+, Windows 10+ (x64) nothing
oscat-<version>-portable-linux-x86_64.tar.gz any 64-bit Linux, no install glibc 2.28+
oscat-<version>-portable-windows-x64.zip Windows Server 2016+, Windows 10+, no install nothing

The two portable downloads install nothing: you unpack them and run OSCAT from the folder, with its data kept inside that same folder. They suit a client jumphost that forbids installing software or where you have no administrator rights. See Portable (no install) below.

Each one is complete, so the jumphost needs no internet access and nothing else installed first. It ships with no benchmarks: you import your own on the Benchmarks page (or by importing a CIS PDF) after the first run. Download on a connected machine, check the file, and copy it across:

sha256sum -c SHA256SUMS --ignore-missing

The jumphost needs network access to the audited hosts: SSH (22), WinRM (5986, or 5985 over HTTP) and HTTPS (443) for APICs. Browsers reach OSCAT on https://<jumphost>:8443.

Linux package (.rpm / .deb)

sudo dnf install ./oscat-*.x86_64.rpm                          # RHEL, Rocky, Alma
sudo zypper install --allow-unsigned-rpm ./oscat-*.x86_64.rpm   # SUSE
sudo apt install ./oscat_*_amd64.deb                           # Ubuntu, Debian

The package:

  • creates an oscat system user;
  • creates the master key /etc/oscat/master.key, which encrypts stored passwords and keys;
  • creates a self-signed HTTPS certificate in /etc/oscat/tls/;
  • prepares its data folder /var/lib/oscat;
  • starts the oscat service (and enables it at boot);
  • prints a setup code for the first administrator:
OSCAT is installed. Open https://jumphost.example:8443 in a browser and create the first
administrator with this setup code:

    9b7b-93a3-9c7e-caa2

Continue with First run and administration.

If browsers connect from other machines, open port 8443:

sudo firewall-cmd --add-port=8443/tcp --permanent && sudo firewall-cmd --reload   # RHEL, SUSE
sudo ufw allow 8443/tcp                                                           # Ubuntu
What Where
Program /opt/oscat
Settings /etc/oscat/oscat.env
Master key /etc/oscat/master.key
Certificate /etc/oscat/tls/cert.pem, key.pem
Data (scans, targets, profiles) /var/lib/oscat
Service systemctl status oscat, logs with journalctl -u oscat

Upgrade by installing a newer package the same way; it keeps the key, settings and data, and restarts the service. Uninstall with dnf remove oscat or apt remove oscat; /etc/oscat and /var/lib/oscat stay until you delete them.

Docker installer (.run)

On any Linux host with Docker and Compose v2:

sudo sh oscat-*-docker.run              # installs in /opt/oscat-docker on port 8443
sudo sh oscat-*-docker.run --dir /srv/oscat --port 9443   # elsewhere

It carries everything OSCAT needs, so it also needs no internet. It writes its settings to /opt/oscat-docker/.env, creates the master key and a self-signed certificate, starts OSCAT and prints the setup code. The containers restart with Docker at boot.

  • Settings: /opt/oscat-docker/.env, then docker compose up -d in that folder.
  • Upgrade: run a newer .run file the same way; data, key and settings are kept.
  • Uninstall: sudo sh /opt/oscat-docker/uninstall.sh keeps the data; add --purge to delete it too.

Windows installer (.exe)

Run oscat-<version>-setup.exe as an administrator. It installs OSCAT in C:\Program Files\OSCAT, keeps settings, key, certificate and data in C:\ProgramData\OSCAT (readable by administrators and the service only), opens TCP 8443 in Windows Firewall and starts the OSCAT Windows service. The last page shows the address and the setup code.

  • Settings: C:\ProgramData\OSCAT\oscat.env (Start menu: OSCAT settings), then Restart-Service OSCAT. Logs are in C:\ProgramData\OSCAT\logs.
  • Unattended: oscat-<version>-setup.exe /VERYSILENT /SUPPRESSMSGBOXES; the setup code is then only in C:\ProgramData\OSCAT\setup-code.
  • The installer adds oscat and oscat-server to the system PATH.
  • Upgrade by running a newer installer; uninstall from Apps or Programs and Features. Both keep C:\ProgramData\OSCAT.
  • A Windows jumphost scans Linux over SSH, Windows over WinRM and APICs over HTTPS. It cannot scan itself as a "This server (local)" target.

Portable (no install)

The portable downloads run OSCAT from a folder without installing anything, which is useful on a client jumphost that forbids installing software or where you have no administrator rights. Like the installers they carry their own Python, every library and the browser UI, so they need no internet. They ship with no benchmarks: you import your own after the first run.

Linux (oscat-<version>-portable-linux-x86_64.tar.gz):

tar -xzf oscat-*-portable-linux-x86_64.tar.gz
cd oscat
./start.sh

Windows (oscat-<version>-portable-windows-x64.zip): unzip it and run start.cmd (double-click, or run it in a command prompt).

The first run creates a data/ folder, a self-signed certificate and a setup code, then serves the web UI on https://localhost:8443. Open that address and create the first administrator with the setup code shown, then continue with First run and administration. Stop the server with Ctrl+C (Linux) or by closing the window (Windows).

  • The portable copy listens on localhost only by default. To reach it from other machines, start it with OSCAT_LISTEN=0.0.0.0 set and open port 8443 in the firewall.
  • Administer it with oscat-server and scan from the command line with oscat, run from the folder (./oscat-server.sh and ./oscat on Linux; oscat-server.cmd and oscat.cmd on Windows). For example ./oscat-server.sh create-user alice --role auditor.
  • Everything is in the folder's data/: the database, the master key (data/master.key) and the certificate. Back up data/master.key separately; without it, stored credentials cannot be decrypted.
  • Upgrade by unpacking a newer portable over the folder (or copy your data/ folder into the new one); your settings, scans and credentials are kept.
What Where
Program the unpacked folder (python/, ui/)
Data, key, certificate data/ inside that folder
Settings environment variables set by the launchers (oscat-env.sh / oscat-env.cmd)

Optional: a local AI model for PDF import

PDF import works without a model. To let a local AI model improve the drafts OSCAT was unsure about, install Ollama on the jumphost, copy in a model pulled on a connected machine (ollama pull qwen2.5:7b, then copy ~/.ollama/models), and set in the settings file:

OSCAT_IMPORT_LLM=ollama
OSCAT_IMPORT_MODEL=qwen2.5:7b
OSCAT_OLLAMA_URL=http://127.0.0.1:11434

A 7B model fits on 12 GB of RAM without a GPU; qwen2.5:14b drafts better with more memory. For Docker installs, start Ollama with OLLAMA_HOST=0.0.0.0 so the containers can reach it. See Importing a CIS benchmark PDF.
