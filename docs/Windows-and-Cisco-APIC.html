Windows, Cisco APIC and network devices

Most CIS Windows settings are described as Group Policy paths in the GUI, Cisco APIC is managed from a web console, and routers, switches and firewalls have their own command line. OSCAT audits all of them without a GUI: it reads the place where each setting is actually stored.

Windows

Connecting

Windows hosts are audited over WinRM (PowerShell Remoting). Use an account in the host's local Administrators group; there is no privilege escalation on Windows.

A new scan with a Windows benchmark logs in over WinRM:

Field Choices
Transport HTTPS (recommended) or HTTP (encrypted messages): Negotiate/Kerberos still encrypts each message. Set the port in the Port box (5986 and 5985 by default).
Certificate check Trust on first use (the default: pins the certificate a host shows the first time and stops if it changes later, so self-signed WinRM certificates work), Verify against OSCAT_CA_BUNDLE or the system store, or Ignore (not recommended)
Advanced → Windows authentication Negotiate (the default: Kerberos, then NTLM), Kerberos, NTLM, CredSSP, Basic (local accounts, HTTPS only)

For domain accounts write the user as CORP\auditor or auditor@corp.example.com. Set OSCAT_CA_BUNDLE in the settings to the CA that signed the hosts' WinRM certificates.

To enable WinRM over HTTPS on a host, an administrator typically runs winrm quickconfig -transport:https with a server certificate in place, or deploys it by Group Policy.

Windows checks

Profiles read Windows settings with these check types; the value read is kept as evidence.

Check Reads Prints
registry: {key, value} a registry value the value (one line per item of a multi-string), nothing if absent
secpol: {setting} secedit /export (password, lockout and other security policy) the setting's value
user_right: {right, format: sid} user rights assignment one account per line, sorted
auditpol: {subcategory} auditpol /get /subcategory (name or GUID) e.g. Success and Failure
service: {name, property} Get-Service the start type or status, NotInstalled if absent 
checks:
  - id: length
    secpol: {setting: MinimumPasswordLength}
    privilege: root
    assert: {num: {op: gte, value: 14}}
  - id: smb1
    registry: {key: 'HKLM\SYSTEM\CurrentControlSet\Services\LanmanServer\Parameters', value: SMB1}
    assert: {equals: "0"}
  - id: tcb
    user_right: {right: SeTcbPrivilege, format: sid}
    assert: {empty: true}
  - id: spooler
    service: {name: Spooler, property: start_type}
    assert: {in_set: [Disabled, NotInstalled]}

A run: check with shell: powershell runs any other PowerShell command. See profiles/cis-windows-server-2022 for a sample.

Hosts without WinRM can be audited with the offline collector (PowerShell).

Cisco APIC

Connecting

An APIC (the Cisco ACI fabric controller) is audited through its management interface, reading the same settings its web console shows. OSCAT only reads, never changes anything, and signs out at the end, so a read-only APIC user is enough.

When adding the target, choose Cisco APIC (REST API), with HTTPS on port 443. For a login domain such as TACACS, write the user as apic#TACACS\auditor. Certificate checking works as for WinRM.

APIC checks

A rest check names the APIC object to read and the setting to pick out of it:

checks:
  - id: http
    rest:
      path: /api/mo/uni/fabric/comm-default/http.json    # or /api/class/<class>.json
      query: {rsp-subtree: "no"}                          # optional
      select: imdata[*].commHttp.attributes.adminSt       # keys, * and [*] / [n]
    assert: {equals: disabled}

CIS has no APIC benchmark, so the bundled profiles/cisco-apic-baseline is OSCAT's own baseline, marked for review.

Network and firewall devices

Routers, switches and firewalls don't give a shell: an SSH login lands in the vendor's own command line. OSCAT audits them over that CLI, reading show (or get) output. It only reads, never changes anything, so a read-only account is enough.

Connecting

A new scan with a network benchmark logs in over the device CLI (or the APIC REST API):

Field Choices
Login credential an SSH password or key for a read-only account on the device
Device type picks the command that turns off output paging — Cisco IOS/IOS-XE, IOS XR, NX-OS, ASA, Arista EOS, Juniper Junos, Palo Alto PAN-OS, Fortinet FortiOS, HPE Comware, HPE Aruba, HPE Aruba CX, Extreme SLX-OS, or Generic
Host key check as for SSH (trust on first use, strict, or ignore)
Advanced → Connect through (SSH bastion) a saved Linux host to go through, if the device is only reachable from there
Enable mode tick to enter privileged mode after login (Cisco/Arista enable)
Enable secret a password credential for the enable secret, or leave it as the login password when the account already has enable rights

Devices that log straight into the mode their audits read from (Juniper, Palo Alto, Fortinet) don't need enable mode.

Network checks

A CLI check sends a device command and judges its text output, so a benchmark for any such appliance works once its checks are written as run: with shell: cli:

profile:
  platform: network
controls:
  - id: ssh-timeout
    title: Idle SSH sessions time out
    checks:
      - id: timeout
        run: show running-config | include line vty|exec-timeout
        shell: cli
        assert: {contains: "exec-timeout 10 0"}

CIS has no bundled network profile (the benchmarks are licensed), so import the device's CIS PDF like any other (see Importing a CIS PDF) and write each check as a show command.

Inventory examples (command line)

hosts:
  win1:
    address: 10.0.0.31
    connection: winrm
    username: CORP\auditor
    password: {env: OSCAT_WIN_PASSWORD}
    scheme: https                 # https (5986, default) | http (5985)
    winrm_auth: negotiate         # negotiate | kerberos | ntlm | credssp | basic
    cert_validation: /etc/oscat/ca.pem   # true | false | CA bundle path
  apic1:
    address: apic1.example.net
    connection: apic
    username: apic#TACACS\auditor
    password: {env: OSCAT_APIC_PASSWORD}
    cert_validation: /etc/oscat/ca.pem
  switch1:
    address: 10.0.0.9
    connection: cli
    username: auditor
    password: {env: OSCAT_NET_PASSWORD}
    platform: cisco-ios           # see the device-type list above; generic by default
    enable: true                  # enter privileged mode after login
    enable_password: {env: OSCAT_ENABLE_SECRET}   # omit to reuse the login password
