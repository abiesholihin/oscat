Network devices

Routers, switches and firewalls are audited through their own command line: OSCAT logs in over SSH, runs the benchmark's show commands and judges the output. A read-only account that can run show (or get, display) commands is enough. Supported: Cisco IOS and IOS-XE, IOS XR, NX-OS and ASA, Arista EOS, Juniper Junos, Palo Alto PAN-OS, Fortinet FortiOS, HPE Comware, Aruba and Aruba CX, Extreme SLX-OS, and any other device whose checks are written as device commands.

Import the benchmark

Import the device's CIS PDF on the Benchmarks page (see Importing a CIS PDF). OSCAT recognises a network benchmark from its title (Cisco, Juniper, Palo Alto, Fortinet, Check Point, F5 and others) and drafts each audit command, such as show running-config | include aaa new-model, as a device command.

The draft pass rule comes from how the benchmark words the result:

The benchmark says The draft passes when
an output means compliant ("If an output is displayed, the system is compliant") the command shows any line
no output means compliant the command shows nothing
a 'no' in the result means the feature is off no line starts with no
a Junos line count of 0, or of at least 1 Count: 0 lines, or a count of 1 or more
only a sample output, under a filtered show the command shows any line (flagged for review)

When the title names one setting to turn on, such as "Enable 'aaa new-model'", and the command reads that setting, the rule also requires that setting in the output, so an empty output never passes. A title alone ("Set 'service tcp-keepalives-in'") gives a rule at low confidence, for review. Where the benchmark needs a count of your own peers or classes, a value from your site, or a threshold, the check keeps its output for you to write the rule. Controls CIS marks Manual keep the command and its output as evidence only.

Scan over the network

Pick the network benchmark on New scan. The login is Network / firewall device (CLI) with the device type (it picks the command that turns off paging) and, for Cisco and Arista, an optional enable secret.

Devices OSCAT cannot reach

For devices with no SSH path from OSCAT, the device admin runs the commands and sends you the log:

  1. Open the benchmark and click Device command list. Choose the whole benchmark or a control set, and download the list. Checks that only filter the configuration (show running-config | include ...) are answered from the full configuration, so the list stays short.
  2. The admin logs in to the device with terminal logging on (PuTTY session logging, SecureCRT log file, or a recorded privileged session), turns off paging (terminal length 0, set cli screen-length 0, ...), and pastes the list.
  3. On Scans → Upload collected results, choose Network device sessions, pick the benchmark, and upload the logs, one file per device.

OSCAT finds each command by its echo after the device prompt, and judges its output like a network scan. The device name comes from its configuration (hostname) or its prompt.

If all you have is a saved running configuration, upload that instead. Checks it can answer are judged; the others (for example ones that read show version) are reported as Manual with "not assessed" and the command that would answer them.

Secrets are masked. Before anything is stored, password hashes, keys, pre-shared keys and SNMP communities in the output are replaced with <masked>. The secret's type stays (for example enable secret 9 <masked>), since that is what the benchmark checks, and the well-known communities public and private stay visible because the benchmark looks for them. The uploaded file itself is not kept.
